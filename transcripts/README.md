# قرارداد نگهداری Transcriptها

این پوشه مرجع متن خام و زمان‌بندی‌شده منابع ویدیویی پروژه است.

هر قاعده، مثال تاریخی یا ادعای استخراج‌شده از ویدیو باید بتواند به یک Source ID، فایل Transcript و تایم‌استمپ مشخص متصل شود.

این فایل مرجع اصلی تمام قواعد اختصاصی پوشه `transcripts/` است. هر عامل هوش مصنوعی باید پیش از ایجاد، ویرایش، جابه‌جایی یا حذف فایل در این پوشه، این سند را بخواند و رعایت کند.

در صورت تعارض میان این سند و `../AGENTS.md`، دستور سراسری `AGENTS.md` اولویت دارد و عامل نباید تعارض را به‌صورت خودکار حل کند.

## محدوده قرارداد

این قرارداد برای تمام فایل‌های داخل مسیر زیر اعمال می‌شود:

```text
transcripts/
```

## پیش‌نیاز ثبت Transcript

پیش از ایجاد فایل Transcript:

1. یک Source ID یکتا در `../knowledge/sources.md` ثبت کن.
2. عنوان، URL، ناشر و تاریخ منبع را تا حد ممکن بررسی کن.
3. منشأ Transcript را مشخص کن:
   - زیرنویس رسمی
   - زیرنویس خودکار
   - استخراج دستی
   - سرویس خارجی
4. مجازبودن ذخیره و بازتوزیع متن کامل را بررسی کن.
5. مسیر فایل Transcript را در رکورد همان منبع ثبت کن.

## قرارداد نام‌گذاری

نام فایل باید دقیقاً با Source ID یکسان باشد:

```text
SRC-0001 → transcripts/SRC-0001.md
SRC-0002 → transcripts/SRC-0002.md
```

استفاده از عنوان ویدیو، تاریخ یا نام ناشر به‌جای Source ID در نام فایل مجاز نیست.

هر Source ID فقط باید به یک فایل Transcript اصلی اشاره کند.

## قالب فایل

```markdown
# SRC-0001 — عنوان ویدیو

- Source ID: SRC-0001
- URL:
- Publisher or analyst:
- Publication date:
- Recording date: unknown
- Transcript source: official | automatic | manual | external_service
- Transcript language:
- Processing date:
- Raw transcript preserved: true | false
- Review status: unreviewed | needs_review | reviewed
- Copyright or access notes:

## Transcript

[00:00:00] متن خام...

[00:00:15] متن خام...
```

## قواعد حفظ متن خام

- متن استخراج‌شده باید تا حد ممکن بدون بازنویسی معنایی حفظ شود.
- خطاهای احتمالی تبدیل گفتار به متن نباید بی‌صدا اصلاح شوند.
- متن خام نباید برای پشتیبانی بهتر از یک قاعده تغییر کند.
- حذف یا تغییر تایم‌استمپ بدون مراجعه دوباره به منبع مجاز نیست.
- فاصله‌گذاری و قالب Markdown را می‌توان اصلاح کرد، مشروط بر اینکه متن، اعداد و معنا تغییر نکنند.
- بخش‌های حذف‌شده یا ناموجود نباید با حدس تکمیل شوند.

## ثبت اصلاحات احتمالی

اصلاح نامطمئن باید از متن خام جدا باشد:

```markdown
> Unverified correction:
> عبارت خام: «...»
> تفسیر احتمالی: «...»
> دلیل:
```

اصلاح نامطمئن نباید جایگزین عبارت خام شود.

مواردی که بر استخراج دانش یا تحلیل اثر دارند باید در فایل زیر نیز ثبت شوند:

```text
../knowledge/ambiguous_items.md
```

## وابستگی‌های تصویری

اگر فهم یک قسمت به نمودار، رنگ، فلش، سطح قیمت، عدد روی صفحه یا هر عنصر تصویری وابسته است:

- در Transcript مشخص کن که بخش نیازمند بررسی تصویر است.
- مورد را در `../knowledge/ambiguous_items.md` ثبت کن.
- قاعده مرتبط نباید فقط براساس Transcript وضعیت `verified` بگیرد.

نمونه برچسب:

```text
[needs_visual_review]
```

## ارتباط با پایگاه دانش

هر ادعای استخراج‌شده باید زنجیره ردیابی زیر را حفظ کند:

```text
Source ID
  ↓
Transcript path
  ↓
Timestamp
  ↓
Rule ID or Example ID
```

قبل از ثبت یا تأیید قاعده بررسی کن که:

- Source ID در `../knowledge/sources.md` وجود دارد.
- مسیر Transcript صحیح است.
- تایم‌استمپ مورد استناد در فایل وجود دارد.
- متن شاهد با قدرت ادعای ثبت‌شده سازگار است.

## حق نشر و محدودیت دسترسی

فقط محتوایی را در مخزن نگهداری کن که ذخیره و بازتوزیع آن مجاز باشد.

اگر نگهداری Transcript کامل مجاز نیست، فقط موارد زیر ثبت شوند:

- Metadata منبع
- تایم‌استمپ‌های ضروری
- نقل‌به‌معنای محدود و وفادار
- یادداشت محدودیت دسترسی

در این حالت مقدار زیر ثبت شود:

```text
Raw transcript preserved: false
```

نباید برای دورزدن محدودیت دسترسی یا حق نشر، متن کامل را به چند فایل یا بخش کوچک تقسیم کرد.

## تغییر، جابه‌جایی و حذف فایل

- تغییر نام فایل فقط زمانی مجاز است که Source ID نیز طبق یک تغییر کنترل‌شده اصلاح شود.
- جابه‌جایی فایل باید همراه با اصلاح تمام ارجاعات در `../knowledge/` انجام شود.
- حذف Transcript نباید باعث حذف سابقه Source ID شود.
- در صورت حذف فایل به‌دلیل حق نشر یا دسترسی، دلیل حذف در `../knowledge/sources.md` ثبت شود.
- تغییرات مهم باید در یک Commit یا Pull Request قابل بازگشت انجام شوند.

## کنترل نهایی

پیش از ثبت تغییر بررسی کن:

- Source ID در `../knowledge/sources.md` وجود دارد.
- نام فایل با Source ID یکسان است.
- URL و Metadata ساخته نشده‌اند.
- تایم‌استمپ‌ها حفظ شده‌اند.
- اصلاحات نامطمئن از متن خام جدا هستند.
- وابستگی‌های تصویری ثبت شده‌اند.
- مسیر Transcript در رکورد منبع صحیح است.
- ارجاعات Rule ID و Example ID معتبرند.
- محدودیت‌های حق نشر رعایت شده‌اند.
- هیچ کلید API، رمز عبور، عبارت بازیابی یا اطلاعات محرمانه‌ای در فایل وجود ندارد.
